Client mockups

Every view of the AnotherCrewLink client, at the size it really is, built from the same components as the design system. These exist to be compared against an implementation — open one beside your build and check it, or screenshot both and diff.

The client window is resizable: frameless, 250px minimum, ~400 typical, no maximum. So no window mockup is one fixed picture — drag the purple grip, hit a preset, or pass ?w=&h=. A layout that only works at 400px is not finished.

How to verify with these

Step
?bare=1Strips the toolbar and the callouts: the frame alone, at exactly the stated size. This is the reference to screenshot against your build.
?w=250&h=520Any size. Verify the 250px minimum with a full fifteen-player lobby, not just the default width.
measures · aDimension callouts, measured off the live DOM rather than written down, so they cannot drift from the layout.
8px grid · gThe client's spacing step. Everything structural should land on it; MUI's own 4px radius does not.
[ · ]Step the width by 10px and watch for the reflow break — the roster changes count per row, the lobby table starts scrolling sideways.

What to check, and what not to

Check: what every control does, what each state communicates, the order of things, the reflow, the colour meanings, and that nothing is drawn for a healthy state.

Do not check: pixel parity. The client is being reimplemented in Rust with egui, and the spec grants that layout, spacing and control affordances will differ. Numbers here are intent, not contract — see egui-implementation.md.
