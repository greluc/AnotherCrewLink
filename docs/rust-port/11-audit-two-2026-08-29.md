# 11 — Audit of the code the first audit never opened, 2026-08-29

The first audit ([10](10-audit-2026-08-29.md)) ended with a list of what nobody had looked
at: the whole of `acl-game`, `acl-ipc` and `acl-helper`, `acl-core`'s platform layer, the
effects half of the mix graph, and the interface. This is that list, audited the same way —
eight parallel finders, every finding handed to a sceptic told to refute it, a completeness
critic at the end.

**Thirty-three findings survived. Seven were refuted.** Three more came from the critic.

The first audit found a client whose *network* did not repair itself. This one found a
client whose *game reader* does not either, and the two failures rhyme: a thing that can
only go wrong once, and no code path that notices it has.

---

## A. The game goes away and never comes back

### A1 ⚠ `read_state` cannot fail, so the helper never re-attaches

`crates/acl-game/src/reader.rs:341` · `crates/acl-helper/src/main.rs:445`

`read_state` is declared `-> Result<AmongUsState, ReadError>` and every fallible read
inside it is hedged: `follow(...).unwrap_or(0)`, `read_u32_at(...).unwrap_or(4)`,
`read_i32_at(...).unwrap_or(-1)`. The body ends unconditionally at `Ok(AmongUsState { … })`.
It is infallible for *any* `ProcessMemory`, including one whose every read fails.

So `Sampler::sample` is infallible, so the `else` arm in the helper — whose comment reads
*"The game went away … a player restarting the game should get their proximity back without
restarting the client"* — is **dead code**. `Sampler::attach` is called once per helper
process, and the handle is held for its whole life.

What happens when the game exits is worse than nothing: every read fails to zero,
`gameState` falls back to 4, `lobby_code_int` to −1, the code becomes `""`, and
`lobby_code_for` turns that into `"MENU"`. The helper emits **well-formed menu frames at
5 Hz, for ever.** The client sees a menu, so it leaves the voice room and never rejoins —
nobody hears anybody, the lobby is unpublished, and the title bar says "Menu". Recovery
needs the ⟳ button or a restart.

`GameReader.ts:203` runs `checkProcessOpen()` every thirty iterations and re-attaches within
about six seconds.

### A2 ⚠ The offsets store is unreachable

> **Fixed 2026-08-29**, both halves. The lookup and the mirror in `4b1fea58`; the build
> key later the same day, in the protocol change described further down. The finding is
> left as written because it is why both exist.

`crates/acl-client/src/reader.rs:266`

No lookup, no `broadcastVersion` scan, no mirror fetch. The client runs on the compiled-in
floor and nothing else, which means a game update breaks it until a new client ships —
`offsetStore.ts` exists precisely so it does not.

### A3 ⚠ An elevated game reads as "no game", for ever, silently

`crates/acl-core/src/launch.rs:162` · `crates/acl-client/src/reader.rs:245`

`ERROR_ACCESS_DENIED` from `OpenProcess` is not distinguished from "process not found", and
nothing re-launches the helper through UAC. The elevation path exists and has no caller. A
player who runs Among Us as administrator gets no game state, no prompt, and no explanation.

## D. Audio

### D1 A non-finite hearing range panics the mixer thread
`crates/acl-audio/src/panner.rs:93` — and release builds abort. The coordinate that
produces it is D6.

### D2 The resampler's chunk is 960 frames at every rate
`crates/acl-client/src/audio.rs:782` — so a 16 kHz microphone emits three 20 ms frames in

`crates/acl-client/src/audio.rs:851` — in `Voice.tsx` the analyser is upstream of the gain

`crates/acl-client/src/audio.rs:874` — so the output callback's `try_lock` loses and whole

### D5 The reverb is panned after convolution
`crates/acl-client/src/audio.rs:1327` — the whole three-second tail is re-placed from the
ghost's current position every frame.

`crates/acl-game/src/reader.rs:427` — the Electron reader turns it into 999 and this one
does not.

### D7 A haunting ghost's tail is cut when they walk out of earshot

### A2's other half was a protocol change, and it was made

> **Done 2026-08-29, later the same day.** What stood here said the lookup could only be
> keyed by `default`, because the build hash lives in the game's memory and offsets are
> sent once, at start, before the helper has attached to anything. The second half of that
> was the fixable part.

The pipe speaks version 2. The core sends the lookup's `patterns` object in the handshake
alongside the `default` guess; the helper scans `GameAssembly.dll` with it on its first
attach, reads the build number out of the `mov ecx, imm32` the version broadcast compiles
to, and volunteers `HelperMessage::Attached { is_64bit, build }` before its first frame.
The core then fetches the file that build wants and sends a second `SetOffsets`, which the
helper already knew how to act on — it drops its sampler and re-resolves every signature.

Volunteered rather than asked for, because the core cannot know when the helper has
attached: a `GetBuild` request would have to be polled, and every poll is a full-module
scan of a process that is usually not running.

The guess still goes across, and for both architectures, because a helper with no bundle
for the game's width does not attach at all and would never get far enough to read a
build. What the build changes is the file that follows.

Three things were made to hold along the way. The patterns are **validated before they are
sent** — `Lookup::validate` now checks the broadcast signature on the same footing as the
offsets, because this is the one thing a file from the mirror contributes to what the
elevated process does, and an empty one is refused rather than tolerated. The fetch for
the reported build runs on **a thread of its own**, because the reader's thread is the one
draining game state and an unreachable mirror would otherwise stop proximity for the whole
timeout. And when that fetch fails there is **no fall back to the compiled-in floor**: the
store refuses to serve it for a build it does not describe, and doing it anyway here would
be exactly the thing that refusal exists to prevent — offsets for a different game. The
helper keeps the guess and the log says so.

### B6 was a feature this port had not built, and now has

> **Done 2026-08-29.** What stood here said drawing names needs a font, a glyph rasteriser
> and a name column, and that `acl_ui::sprite` has none of the three. All true. The first
> two turned out to be in the tree already.

`egui` is a direct dependency of `acl-ui` and re-exports `epaint`, which embeds a font and
rasterises it. So `acl_ui::text` lays a name out with `Context::fonts_mut`, reads the
coverage out of the font atlas and blits it into the same premultiplied BGRA the rest of
the overlay is — **no new crate, no `.ttf` in the repository and no licence to account
for**. The alternatives were a bitmap font written here, which would draw a Cyrillic or
CJK name as a row of boxes, or a rasteriser crate plus a face, which is two entries in the
dependency review for a label.

The column is a separate field on `Layout` rather than more entries in `sprites`, because
`sprites` means "a crewmate" to everything that reads it — including the test that checks
every one of them is inside the strip. A name is a *box*, not a point: names are not all
one width, and the caller fits the rasterised text into it, which is also what clips one
too long for the strip. Flush against the crewmates and ragged on the outside, which is
`overlay.css:108-114` and is the edge a reader's eye follows down the column.

Three things are not the shipped overlay's, and are deliberate. The **size** is a fraction
of the crewmate rather than of the game window: `overlay.css` sizes text in `vh` and this
layout does not work in `vh`, so the name is kept proportional to the thing it labels. The
**vertical placement** is centred on the crewmate rather than dropped by `3vh`, for the
same reason. And a name **too long for its box loses its far end** instead of running over
the game: 1.x can do that because it is a web page over a window, and this is a fixed
buffer.

The pipe buffer went from 384 KiB to 768 KiB with it. A name plate is its own sprite, and
a full lobby's fifteen took the frame to roughly 495,000 bytes — back over the old buffer,
which is finding B2 again by a different route.

**Untested where it counts, and that has not changed.** No test here draws the overlay on a
screen; what is tested is the geometry, the plate and the premultiplication. The audit's
own reason for deferring this — that it puts a text path into the one surface nobody here
can look at — still applies, and the finding that names are on by *default*
(`overlayPosition` is `right`, `compactOverlay` is false) makes it sharper rather than
softer. Every failure path draws no name rather than a broken one, which is the most that
can be done without eyes on it.

## Refuted — do not raise these again

- `reader.rs:269` `oldGameState` produced and never read. It is read.
- `link.rs:178` nothing bounds a silent helper. There is a deadline and it is applied.
- `link.rs:333` no `log` implementation anywhere. `acl_core::logging` installs one; what
  audit 1 found (C1) is that it is installed *late*, after the transport's warnings.
- `audio.rs:669` the reference divided by an unwritten channel count.
- `net.rs:831` every close reason discarded, including the retirement sentence.
- `session.rs:519` `setHost` read by nothing.
- `server_url.rs:44` `is_valid` has zero callers. It has one.

## Method

Identical to audit 10, on the eight dimensions the first left out: reading the game out of
process memory, the state it publishes, the named pipe and the overlay helper, the platform
layer, the effects half of the mix graph, the newest audio code, the Engine.IO and
Socket.IO wire, and the interface with the updater and the translations. Forty-nine agents.
Verification was capped at the five most severe per dimension; everything dropped is in the
run log rather than silently cut.
